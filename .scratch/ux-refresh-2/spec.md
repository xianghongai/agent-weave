# 交互体验调整（第二轮）

Status: done

## 问题陈述

第一轮调整完成后，实际使用中还有这些问题：

- 输出页的提示排在预览下方，预览没法在一屏内滚动，提示读起来也不方便。
- 工具、MCP Server、标签等列表页标题下的说明太长，会折行，挤占高度；Agent 对话框里模板的说明同样冗长，说明中的命令和模板没有代码样式。
- Agent 清单中权限输出与 MCP 输出并排显示，两者高度不一致，不美观；“新增内置工具”看起来不像按钮；对话框的分区标题没有图标；MCP 输出的“风格”选项占的高度太大；作用域名称每次都要手动输入。
- 同步页同时放着预设和本机设置，这两项与同步无关；Gist Token 和 Gist ID 直接显示在页面上，开视频会议或截图时容易泄露。
- 带表单的弹窗点空白处就会关闭，已填的内容随之丢失；各弹窗宽度不一。
- 页脚文案只提到 Gist，以后接入其他同步方式时就不准确了。
- 没有首页，点击 Logo 进入的是权限规则页。

## 解决方案

- 输出页增加第三个 Tab“重要提示”，所有提示都移进去，权限和 MCP 两个 Tab 的预览占满剩余高度。
- 新增共用的帮助气泡 `HelpPopover` 和 Markdown 渲染组件 `<Markdown>`。长说明收进问号，含代码的说明用 Markdown 书写。
- 新增共用的表单弹窗组件，只有窄、宽两档宽度，点空白处和按 Esc 都不关闭。
- 页眉增加设置菜单，本机设置和预设改为从菜单打开的对话框；同步页只保留导入导出和 Gist 同步，Gist 的认证信息放进对话框。
- 调整 Agent 清单和 Agent 对话框的若干细节，作用域名称可以从候选中选择。
- 页脚改成不依赖具体同步方式的文案，并附 GitHub 链接。
- 新增宣传首页 `/`，作为站点的默认入口。

“提示”已作为总称写进 `GLOSSARY.md`；与本轮有关的长期约定已写进 `AGENTS.md` 的“技术约定”和“目录职责”。

## 实现决策

### 共用组件

- **`HelpPopover`**（`src/components/help-popover.tsx`）：问号图标按钮，悬停打开，不考虑触屏。参考鸿爪项目的同名组件（`/home/xiang/Features/hongzhao/src/components/help-popover.tsx`），基于 Base UI 的 `Popover` 加 `openOnHover`。必须带无障碍标签；正文一律用 `<Markdown>` 渲染。现有的 `src/pages/rules/pattern-label.tsx` 改用它。
- **`<Markdown>`**（`src/components/markdown.tsx`）：用 `markdown-to-jsx` 渲染，开启 `disableParsingRawHTML`，用 `overrides` 给行内代码、列表、链接配上站点样式。链接在新标签页打开，并带 `rel="noreferrer"`。选它的原因：体积小，直接输出 React 元素，不需要 `dangerouslySetInnerHTML`。
- **表单弹窗**（`src/components/form-dialog.tsx`）：包装 shadcn 的 `Dialog`，只接受 `size: 'narrow' | 'wide'`，分别对应 `sm:max-w-lg` 和 `sm:max-w-3xl`。点空白处不关闭（Base UI 的 `disablePointerDismissal`），按 Esc 也不关闭（在 `onOpenChange` 中拦截原因为 Esc 的关闭，具体 API 用 context7 查证）；只能通过关闭按钮、取消或保存关闭。

| 宽度 | 弹窗                                                    |
| ---- | ------------------------------------------------------- |
| 窄   | 标签、命令工具、权限规则、内置工具、Gist 认证、本机设置 |
| 宽   | Agent、MCP Server                                       |

预设对话框和各种确认框（`AlertDialog`）没有输入框，不算表单弹窗：它们可以点空白处或按 Esc 关闭。预设对话框使用窄宽度。

### 说明文字

- 权限规则、工具、MCP Server、标签四个列表页标题下的说明，统一收进标题旁的 `HelpPopover`，页面上不再另起一行。
- 说明的意思不删减，只改写成 Markdown：拆成要点，命令、路径、模板、占位符用行内代码标出。
- 字段说明中含代码的（例如 `${VAR}`、`./src/`、`push --force`）改用 `<Markdown>` 渲染；纯文字的说明保持原样。
- 文案仍然放在 `src/locales/zh-CN.json` 中。插值的值不转义（`escapeValue: false`），因此关闭原始 HTML 解析之后，插入的用户数据也不会被当成标签渲染。

### 输出页

- 内层 Tab 改为三个：权限、MCP、重要提示。“重要提示”这个 Tab 不显示数量；有高危提示时，Tab 名后面显示一个警告色的小圆点，其余情况不显示任何标记。
- “重要提示”按以下顺序列出：高危提示、冲突提示、跳过的规则、TOML 跳过的字段、占位符未展开。一条都没有时显示“没有提示”。
- 权限和 MCP 两个 Tab 里只保留作用域、预览和复制说明。宽屏下预览占满剩余高度，在代码框内部滚动；窄屏仍是整页滚动。
- “占位符未展开”中加一个按钮，直接打开本机设置对话框，见下文“设置菜单”。

### Agent 页

- **Agent 清单**：卡片中的权限输出和 MCP 输出改为上下两行。“新增内置工具”改为带加号图标的 `outline` 小按钮。
- **Agent 对话框**：基础信息、权限输出、MCP 输出三个分区的标题前加图标，依次为 `InfoIcon`、`ShieldCheckIcon`、`PlugIcon`，后两者与输出页的 Tab 一致。
- **MCP 输出的“风格”**：改用 `TabsList` 做分段选择，样式和本机设置中选择操作系统的控件相同；风格说明收进 `HelpPopover`。
- **模板说明**：命令工具模板、MCP 工具模板和内置工具模板，在“有模式模板”“无模式模板”两个字段名旁边各放一个 `HelpPopover`，不放在分组标题旁边。每个气泡单独就能看懂，各自写明用途、可用的占位符、示例，以及模板为空时规则进入跳过的规则。命令工具的示例：
  - 有模式模板：规则带模式时使用，可用 `{command}`、`{pattern}`。例如 `Bash({command} {pattern} *)`，`git` 加模式 `push` 得到 `Bash(git push *)`。为空时，带模式的规则进入跳过的规则。
  - 无模式模板：规则省略模式、表示整个工具时使用，可用 `{command}`。例如 `Bash({command} *)` 得到 `Bash(git *)`。为空时，不带模式的规则进入跳过的规则。
- **作用域名称**：改为可输入的下拉框，用 shadcn 的 Base UI `combobox` 添加。候选为用户级、项目级、项目本地级，放在文案文件中，也可以输入别的名称，不做校验。选中候选后不自动填写说明；路径不提供候选。
- **预设数据**：Claude Code 权限输出的作用域“本地级”改名为“项目本地级”。Antigravity 的“工作区级”保持不变。不写迁移，已有的工作区通过重置为预设获得新名称。

### 设置菜单

- 页眉中主题切换的左边加一个齿轮按钮，点击后弹出下拉菜单（shadcn 的 Base UI `dropdown-menu`），菜单项为“本机设置…”和“预设…”。
- 这两个对话框可以从多个地方打开（菜单、输出页的提示），所以当前打开的是哪个对话框记在 `ui-store` 中，例如 `openDialog: 'deviceSettings' | 'presets' | null`。对话框挂在应用外壳上，任何页面都能打开。
- **本机设置对话框**：使用窄宽度的表单弹窗，内容与现在的“本机设置”一节相同。改为编辑草稿，点“保存”才写入 store，点“取消”放弃修改；展开示例跟随草稿实时变化。
- **预设对话框**：内容与现在的“预设”一节相同，包括合并、重置和跳过报告；重置仍需经过确认框。
- 同步页删除“预设”和“本机设置”两节，只保留“导入与导出”和 Gist 同步。

### Gist 认证

- 同步页上的 Gist 卡片只显示：
  - 状态：已配置 Token、已关联 Gist，或者缺少哪一项、Gist ID 无效；
  - 三个按钮：“认证配置”“推送”“拉取”。
- 页面上不出现 Token、Gist ID 和 Gist 链接。
- “认证配置”打开窄宽度的表单弹窗，里面放 Token 指引、两个创建链接、安全警告、Token、Gist ID，以及“打开 Gist”链接。改为编辑草稿，点“保存”才写入 store；Gist ID 无效时不能保存。
- 推送成功后新建的 Gist ID 照旧直接写入 store。
- 判断状态的逻辑（有没有 Token、Gist ID 是否有效）写成 `src/lib/gist.ts` 中的纯函数，返回原因码，由界面翻译。
- 这次不抽象“同步方式”这一层。Gist 是一张独立的卡片，以后新增其他同步方式时并排加卡片。

### 页脚

- 左侧：“数据只保存在你的浏览器和你选择的同步位置，本站不收集任何数据”。
- 右侧：GitHub 图标，链接到 `https://github.com/xianghongai/agent-weave`，在新标签页打开，带 `rel="noreferrer"`，无障碍标签为“GitHub 仓库”。`lucide-react` 1.x 已经没有品牌图标，GitHub 标志用一段内联 SVG，放在单独的组件中。
- 不加版权声明。

### 首页

- 新建 `src/pages/home/`，路由 `/` 指向首页，打开站点默认就进入首页。首页不在 `registry.ts` 中登记，不出现在导航里；在首页时导航不高亮任何一项。点击 Logo 回到首页。
- 宽屏下一屏放下，窄屏可以滚动。结构参考鸿爪的首页（`/home/xiang/Features/hongzhao/src/tools/home.tsx`），进场动效用 `motion/react`：
  - 主标语：“一份权限规则，织进每一个 Agent”
  - 介绍：“维护一份与 Agent 无关的权限规则和 MCP Server 清单，生成 Claude Code、Codex CLI、Antigravity…… 各自的配置。全部在浏览器内完成。”不罗列完整的 Agent 名单，也不写具体数量。
  - 三张流程卡片：编写中立规则集 → 配置 Agent → 复制输出。卡片可以点击，分别进入权限规则页、Agent 页和输出页。
  - 主按钮：“开始编写规则”，进入权限规则页。
- 原来“`/` 显示第一个登记页面”的逻辑删除；未匹配的路由仍按现有方式处理。

## 测试决策

- `test/` 仍然只测纯函数。
- 新增 Gist 设置状态判断的测试，覆盖这几种情况：都没填、只有 Token、只有 Gist ID、Gist ID 无效、填的是 Gist 网址、两项都有效。
- 预设改名后，现有的预设和生成测试要相应更新，并且全部通过。
- 涉及界面的改动都要在浏览器中实际验证：宽屏和窄屏的布局、弹窗点空白处和按 Esc 都不关闭、问号气泡悬停打开、Markdown 的行内代码样式、深浅两种主题；并确认运行时只向 `api.github.com` 发出请求。

## 不在范围内

- “同步方式”的抽象，以及 Gist 以外的同步方式。
- 帮助气泡在触屏上的交互。
