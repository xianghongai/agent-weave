# 04: 预设改为 JSONC 数据文件，构建时合成

**What to build:** 按 spec 的“预设文件与合成”和“CI 与部署”两节，预设从 TypeScript 源码改为仓库根目录 `presets/` 下手写的 JSONC 数据文件，构建时合成一份工作区。站点功能与现在一致：首次使用、合并预设、重置为预设的结果不变（Agent 顺序除外，改为按优先级与文件名排序）。决策依据见 ADR 0004。

**Blocked by:** 01、02

**Status:** done

**Test seam:** 新的预设合成模块（`src/lib/` 中的纯函数，如 `src/lib/preset-composition.ts`）

- [x] `presets/` 下有标签、命令工具、MCP Server、共享规则各一个文件，`agents/` 下每个 Agent 一个文件；每个文件都是一份部分工作区，顶层键与导出文件相同
- [x] 数据沿用现有内容：用一次性脚本（不提交）从现有预设生成，推导出来的规则逐条展开；代码注释中的取舍理由改写成相关条目的描述或 JSONC 注释
- [x] 给人看的文字（标签名、描述、高危说明、Agent 描述、作用域名称与说明、规则描述）写成以条目 ID 为前缀的文案键，中文放在 `presets/locales/` 下的语言文件中，与界面语言文件分开
- [x] Agent 文件顶层的 `priority` 用于排序（降序，省略为 0，同值按文件名），合成后丢弃，不进入工作区；本票先给 Claude Code、Codex CLI 设 100，Antigravity 设 50
- [x] 合成函数输入“文件路径加文本”的列表和语言文件文本，输出工作区加一组警告，语法错误单独返回；不依赖文件系统
- [x] 合成结果经过与导入相同的校验，不通过的原因带条目 ID 作为警告；缺少文案键、键未被使用也作为警告
- [x] 结构版本与固定的旧修改时间由合成代码补上，不写在数据文件中
- [x] 构建插件放在构建目录，只负责读取文件、调用合成函数，并以虚拟模块提供结果：语法错误让构建失败并报出文件名和行列，逻辑问题只出 Vite 警告；开发服务器在预设文件变化时重新合成
- [x] 删除原有的预设 TypeScript 模块；“返回预设工作区的独立副本”这一接口保留，合并预设、重置为预设、持久化回退照常工作
- [x] `presets/README.md` 只讲原则和方法：文件结构、ID 取名约定、优先级、文案键、新增命令时要补规则；不写具体条目
- [x] 测试覆盖合成函数：数组拼接、排序并丢弃 `priority`、文案键替换、缺键与未用键警告、校验问题以警告报出并带条目 ID、语法错误带文件名和行列（使用测试内联的小样本）
- [x] 测试读取 `presets/` 下的实际文件交给合成函数：没有警告，并能通过导入校验；现有预设测试中的语义检查保留
- [x] 新增守卫测试：没有任何规则、又不在豁免名单（`dd`、`mkfs`、`chmod`、`chown`）中的命令工具让测试失败
- [x] GitHub Pages 部署工作流在构建前先运行单元测试
- [x] `AGENTS.md` 的目录职责补上 `presets/`，`docs/agent-formats.md` 改为指向新的预设文件位置
- [ ] 在浏览器中验证：清空本地数据后首次打开得到预设；合并预设与重置为预设正常；故意在预设文件中写错一个引用，构建只出警告、测试失败（后半句已在命令行验证：悬空引用时构建只出 `danglingReference（preset-rule-gh-allow）` 警告、7 个测试失败；语法错误时构建失败并报出 `presets/tags.jsonc:3:3`。浏览器部分待人工确认）
