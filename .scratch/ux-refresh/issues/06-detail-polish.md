# 06: 细节调整

**What to build:** 四处细节：“模式”说明改为问号图标加 Popover 并重写文案；修正有歧义的 Placeholder；本机设置按操作系统分 Tabs，每个系统各存一个用户名；标签的工具数按种类拆开显示，并能带着筛选跳转。

**Blocked by:** 01, 02

**Status:** ready-for-agent

## 模式说明

- [ ] 新增规则表单和规则编辑对话框中，“模式”标签右侧放一个问号图标，原来独占一行的说明移进 Popover；Popover 开启 `openOnHover`，桌面悬停打开，触屏点击打开
- [ ] 三种变体都改，文案如下（`{{agent}}` 为插值）：
  - 命令工具：“填命令后面的部分，按前缀匹配。例如工具为 git、模式为 push，匹配所有以 git push 开头的命令。* 不做转义，由各 Agent 按自己的规则当作通配符。”
  - MCP 工具：“填该 MCP Server 提供的工具名，如 resolve-library-id。* 不做转义，由各 Agent 按自己的规则当作通配符。”
  - 内置工具：“路径填以 / 结尾的目录，如 ./src/，模板会补上 glob。* 不做转义，由各 Agent 按自己的规则当作通配符。该规则只属于 {{agent}}。”

## Placeholder

- [ ] `tools.keyPlaceholder` 改为“如 git”，内置工具的 `keyPlaceholder` 改为“如 Read”
- [ ] 检查 `zh-CN.json` 中其他用“、”列举多个值的 Placeholder，凡是可能被理解成“可以一次填多个”的一并修正（`*Hint` 中的举例不受影响）

## 本机设置

- [ ] 本机设置的结构改为 `{ os, user_names: { linux, macos, windows } }`，直接替换旧结构，不做迁移
- [ ] 同步页的操作系统改为真正的 Tabs，每个系统一个面板，面板里是该系统的用户名输入框；选中的 Tab 就是输出时展开占位符所用的系统
- [ ] 用户名标签显示为“Linux 用户名”“macOS 用户名”“Windows 用户名”；说明中给出对应系统的示例路径 `/home/<用户名>`、`/Users/<用户名>`、`C:\Users\<用户名>`
- [ ] 还没选操作系统时，Tabs 没有选中项，展开结果区域显示现有的“设置不完整”提示
- [ ] 占位符展开改为使用所选系统的用户名；单元测试覆盖：各系统各自的用户名、所选系统的用户名为空、未选系统
- [ ] 本机设置在 `GLOSSARY.md` 中的定义已经更新，实现时与它保持一致

## 标签跳转

- [ ] 在 `src/lib/` 中把标签的工具数改为按种类统计（命令工具、MCP 工具、内置工具），附单元测试
- [ ] 标签列表的徽标拆成“命令工具 n”“MCP 工具 n”“内置工具 n”，数量为 0 的不显示
- [ ] “命令工具 n”和“MCP 工具 n”可以点击，用 `<Link state={{ tagId }}>` 分别跳到工具页和 MCP Server 页；“内置工具 n”不可点击
- [ ] 工具页和 MCP Server 页在初始化筛选的 `useState` 时读取 `history.state` 中的 `tagId`，读取逻辑放在 `src/browser/`；从顶部导航进入时没有筛选，浏览器后退或前进回到带 state 的记录时恢复筛选
- [ ] `tagId` 指向已删除的标签时忽略它，按无筛选处理

## 验证

- [ ] 在浏览器中验证：Popover 的悬停与点击、本机设置切换系统后输出页的路径变化、从标签页跳转后的筛选、后退恢复筛选
