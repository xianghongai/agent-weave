# 落地多语言，增加英文界面与英文预设

Status: ready-for-agent

## 问题陈述

站点是公开的，但界面只有简体中文。不懂中文的访客打开后看不懂任何按钮和说明，也读不懂预设里命令工具、MCP Server、权限规则的描述和高危说明，只能离开。

文案已经集中在语言文件中，纯逻辑也只返回原因码，但语言写死为简体中文：没有第二种语言，没有切换入口，日期按中文格式显示，`<html lang>`、页面描述和 PWA 清单都固定为中文。预设的文字在构建时只按中文合成，进入工作区后就是中文数据。

## 解决方案

- 界面提供简体中文和英文两种**界面语言**。首次访问时跟随浏览器语言：浏览器偏好中第一个中文标签选简体中文，其余情况选英文。
- 页脚右侧放一个语言菜单，按各语言自己的写法列出语言（简体中文、English）。选择后立即切换，并保存在当前设备上，刷新后保留。界面语言和主题一样只存在本机，不进入工作区、导出文件和 Gist。
- 预设按语言各合成一份，两份都随站点发布。首次初始化、合并预设、重置为预设时，使用当前界面语言的预设。
- 工作区中的文字是用户数据，切换界面语言时不改动。切换语言后再合并预设，工作区可能中英混杂；想要整套另一种语言的预设，可以重置为预设。
- 静态位置（页面描述、初始的 `<html lang>`、PWA 清单的描述和语言）在脚本运行前就已生效，统一写英文；脚本运行后，`<html lang>` 和页面标题跟随界面语言。

决策依据见 ADR 0005。英文术语以 `GLOSSARY.md` 中每个术语的 `_English_` 为准。

## 用户故事

### 不懂中文的访客

1. 作为英文浏览器的访客，我希望首次打开站点就看到英文界面，这样不用先找切换入口。
2. 作为浏览器偏好为日语、其次为英语的访客，我希望看到英文界面，这样不支持的语言也能落到我看得懂的语言上。
3. 作为英文访客，我希望首次使用时工作区里的预设描述、高危说明、标签名和作用域名称都是英文，这样我能判断每条预设规则为什么存在。
4. 作为英文访客，我希望错误、回退、同步、导入失败等提示都是英文，这样出了问题我知道发生了什么。
5. 作为英文访客，我希望说明气泡中的 Markdown 说明（含命令、路径、模板）也有英文版，代码部分保持原样。
6. 作为英文访客，我希望计数文字有正确的单复数形式（如 1 rule、2 rules），这样界面读起来自然。
7. 作为英文访客，我希望时间按英文习惯显示，这样不会看到中文格式的日期。
8. 作为把站点添加到主屏幕的访客，我希望应用描述是英文，这样安装提示看得懂。
9. 作为通过搜索引擎找到站点的访客，我希望页面描述是英文。

### 中文用户

10. 作为中文浏览器的用户，我希望首次打开时看到简体中文界面，与现在一致。
11. 作为繁体中文浏览器的用户，我希望看到简体中文界面，因为它比英文更接近我的语言。
12. 作为中文用户，我希望现有的中文界面和中文预设不受影响。

### 切换语言

13. 作为用户，我希望页脚右侧有语言菜单，并显示当前语言的名称，这样我知道现在是什么语言、到哪里改。
14. 作为用户，我希望菜单中的每种语言都用它自己的写法显示，这样无论界面当前是什么语言，我都能找到自己的语言。
15. 作为用户，我希望选择语言后界面立即切换，不需要刷新。
16. 作为用户，我希望选择的语言在刷新和下次打开时保留。
17. 作为用户，我希望手动选择的语言优先于浏览器语言，即使选的正好和浏览器语言相同。
18. 作为用户，我希望切换语言后，浏览器标签上的页面标题和页面的 `lang` 属性也跟着变，这样屏幕阅读器按正确的语言朗读。
19. 作为离线使用的用户，我希望没有网络时也能切换语言。
20. 作为窄屏用户，我希望语言菜单始终可见，空间不够时由左侧的隐私说明先截断。

### 工作区与预设

21. 作为用户，我希望切换语言不改动工作区中已有的任何文字，这样我自己写的描述不会被覆盖。
22. 作为用户，我希望切换到英文后合并预设，新加入的条目是英文，已有条目保持不变。
23. 作为用户，我希望切换到英文后重置为预设，得到一整套英文预设。
24. 作为用户，我希望本地数据损坏、回退到预设时，预设用我当前的界面语言。
25. 作为用户，我希望切换语言不会产生新的修改时间，也不触发同步，因为工作区没有变化。

### 隐私

26. 作为用户，我希望界面语言只保存在当前设备，不出现在导出文件和 Gist 中。
27. 作为用户，我希望切换语言时不向任何服务器发出请求，语言包随站点打包。
28. 作为用户，我希望本地保存的语言值损坏时，站点静默回到跟随浏览器语言，不弹出提示。

### 维护者

29. 作为维护者，我希望简体中文语言文件仍是键的正本，`t()` 的键仍参与类型检查。
30. 作为维护者，我希望英文缺键、多键、插值变量不一致或文案为空时测试失败，这样运行时不会悄悄显示键名。
31. 作为预设维护者，我希望英文预设语言文件缺键或有多余的键时测试失败，与中文一样。
32. 作为预设维护者，我希望测试保证两种语言合成出的预设只在文字上不同，这样不会出现英文预设少一条规则的情况。
33. 作为维护者，我希望 `AGENTS.md` 写明新增界面文案时要同时补齐英文，预设的写法说明也写明两种语言文件。
34. 作为维护者，我希望只显示一种语言时只加载那一份界面语言包，首屏不多加载另一份。

## 实现决策

### 界面语言模型

- 新增纯逻辑模块“语言”：支持的语言列表 `zh-CN`、`en`（也是菜单中的顺序）；源语言为 `zh-CN`；兜底语言为 `en`；各语言用自己写法的名称；`matchLanguage(tag)` 把 BCP 47 标签映射到支持的语言（主子标签为 `zh` 的都映射到 `zh-CN`，主子标签为 `en` 的映射到 `en`，其余为 `null`）；`resolveLanguage(chosen, preferred)` 先取合法的手动选择，再依次匹配浏览器偏好，最后取兜底语言。
- 结构照 hongzhao 项目的同名模块，去掉繁体中文、日语、韩语和网址参数相关的部分。

### 持久化

- 持久化应用 store 新增 `language: Language | null`，`null` 表示跟随浏览器，与主题放在同一个存储键中；设置它的 action 与主题的写法相同。菜单中选择哪种语言就存哪种，选的和浏览器语言相同时也照存。
- 持久化模块的 `PersistedState` 增加 `language`。`restorePersistedState(persisted, preferred)` 和 `defaultPersistedState(preferred)` 新增参数：浏览器语言偏好列表。
  - 保存的 `language` 不是支持的语言时静默按 `null` 处理，不产生回退原因码，与主题一致。
  - 预设语言 = `resolveLanguage(保存的 language, preferred)`。首次访问的初始工作区，以及工作区回退时用的预设，都用这个语言。
- store 在模块加载时就同步完成恢复。i18n 初始化时读 store 中的 `language`，再交给 `resolveLanguage`，所以界面语言与初始化预设用的语言一致。
- 不写迁移：旧数据没有 `language` 字段，按 `null` 处理。

### i18n 初始化与切换

- i18n 模块提供 `setupI18n()`、`switchLanguage(language)`、`currentLanguage()`，结构照 hongzhao：
  - 每种语言的语言包用动态 `import()` 打包成独立的带哈希脚本，属于 `script-src 'self'`，不占用 `connect-src`；首屏只加载当前语言，另一种在第一次切换时加载。
  - `fallbackLng: false`、`partialBundledLanguages: true`，缺键由测试保证。
  - 初始化和切换后，把 `<html lang>` 设为当前语言，页面标题取 `brand.name`。
  - `switchLanguage` 加载语言包、切换 i18next，并通过 store 的 action 保存选择。
- 格式化时间改为按 `currentLanguage()` 显示。
- PWA 预缓存包含两份语言包，离线时也能切换。

### 语言文件

- 新增英文界面语言文件。简体中文语言文件仍是键的正本，`i18next.d.ts` 不变。
- 英文在有计数的位置使用 i18next 的复数后缀 `_one` / `_other`，中文仍只有一个键；组件按现有方式传 `count`。
- 英文译文按 Microsoft Writing Style Guide：标题和按钮用 sentence case，第二人称，句子简短。术语严格按 `GLOSSARY.md` 的 `_English_`。“Agent Weave”、各 Agent 产品名、命令、路径、模板和 Markdown 中的代码保持原文。

### 语言菜单

- 新增共享组件“语言菜单”，放在页脚右侧、GitHub 图标左边：`[语言图标 当前语言名称 ▾] [GitHub]`。
- 照 hongzhao 的语言菜单，用 shadcn 的 `Select`：触发器透明底、无边框，悬停时显示底色；字号跟随页脚用 `text-xs`；菜单向上弹出，`align="end"`，调用处显式传 `alignItemWithTrigger={false}`；每个选项带对应的 `lang` 属性；触发器的 `aria-label` 取文案键 `footer.language`。
- 窄屏下语言名称始终显示，由左侧的隐私说明截断。

### 预设

- 预设目录新增英文语言文件，键与中文语言文件相同。
- 构建插件对每种语言各调用一次合成函数，`virtual:preset-workspace` 默认导出 `Record<Language, Workspace>`。构建期警告带上语言文件的路径，警告文字仍是中文，不翻译。
- 预设模块的 `createPresetWorkspace(language)` 按语言返回独立副本。`mergePresets` 和 `resetToPresets` 增加语言参数，由界面层传入 `currentLanguage()`；`src/lib/` 不读取 i18n。合并逻辑本身不变，仍按 ID 跳过已有条目。
- 英文预设的译文规则与界面相同。

### 静态位置与文档

- 页面描述、初始的 `<html lang>`、PWA 清单的 `description` 和 `lang` 改为英文。
- `AGENTS.md`：界面提供简体中文和英文；新增界面文案时先加到简体中文，再补齐英文；说明语言包按需加载、不放 `public/` 的理由。
- 预设说明文档：语言文件改为每种语言一个，新增或修改预设文字时两种语言都要补。
- `GLOSSARY.md` 与 ADR 0005 已在设计阶段写好，ADR 0004 的语言文件条目已指向 0005。

## 测试决策

- 好的测试只看外部行为：给定输入，断言得到的语言、状态、工作区或警告，不断言内部的辅助函数。
- **语言（新接缝）**：`matchLanguage` 覆盖 `zh`、`zh-CN`、`zh-TW`、`zh-Hant-HK`、`en-US`、`EN`、`ja`、带空白的标签；`resolveLanguage` 覆盖合法的手动选择优先、非法的手动选择被忽略、按偏好顺序取第一个能匹配的、都不匹配时取 `en`、空偏好列表。参照 hongzhao 的 `language.test.ts`。
- **持久化（主接缝）**：参照现有持久化测试，新增以下用例：
  - 首次访问时，预设的语言由偏好列表决定，`language` 为 `null`；
  - 保存了 `language` 时恢复出这个值；
  - 非法的 `language` 静默变为 `null`，不产生回退原因码；
  - 工作区无效、回退到预设时，预设的语言先取保存的 `language`，没有时取偏好列表。

  用预设中某个已知条目的文字（如某个标签名）判断取的是哪种语言的预设。

- **预设操作**：`mergePresets` 和 `resetToPresets` 按传入的语言取预设。沿用现有测试中替换 `preset` 参数的写法，再补一条不替换、只传语言的用例。
- **预设内容**：现有的预设测试对每种语言都运行：读取实际文件合成，不得有警告，并能通过导入校验。新增一条：两种语言合成出的工作区去掉文字字段（标签名、描述、高危说明、作用域名称和说明）后完全相同。现有快照只保留简体中文一份。
- **语言包一致性**：新增测试，照搬 hongzhao 的 `locales.test.ts`：合并复数后缀后，英文的键集合与简体中文完全相同；每段文字的插值变量与源语言一致；没有空文案。
- **隐私边界**：现有隐私边界测试的 `PersistedState` 加上 `language`，断言导出文件和 Gist 推送都不带它。
- **CSP**：现有 CSP 测试不变，语言包走 `script-src`，`connect-src` 仍只放行 `'self'` 和 `https://api.github.com`。
- 不写单元测试的部分（i18n 初始化与切换、语言菜单、`<html lang>` 与页面标题、PWA 离线切换），在浏览器中实际验证：英文与中文浏览器各打开一次、切换并刷新、窄屏查看页脚，并确认运行时只向 `api.github.com` 发出请求。

## 不在范围内

- 简体中文和英文以外的语言，包括繁体中文。
- 把手动选择的语言写进网址参数。
- 切换语言时重新翻译工作区中的预设文字，或提供“翻译工作区”功能。
- README 双语化（`README.zh-CN.md` 仍是空的占位文件）、文档与 ADR 的翻译。
- 构建期警告（预设插件的警告文字）的翻译：只给维护者看。
- 生成结果的语言：生成结果不含描述，与界面语言无关。

## 补充说明

- 参考实现：本机的 hongzhao 项目中的语言模块、i18n 模块、语言菜单和语言包一致性测试。两处必须不同：语言选择保存在持久化 store 中，而不是网址参数中；只有两种语言。
- 英文译文由实现代理撰写，用户审阅。界面约 520 行、预设约 310 行，按 ticket 拆开后可以并行翻译。
- 语言包按需加载后，首次渲染要等当前语言包加载完成，`main.tsx` 已经是先完成 i18n 初始化再渲染，保持不变。
