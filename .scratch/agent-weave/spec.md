# Agent Weave：权限与 MCP 配置在线生成

Status: done

## 问题陈述

同时使用多个 AI Coding Agent（如 Claude Code、Antigravity、Codex CLI）时，每个 Agent 的权限规则和 MCP 配置格式都不一样。同一套意图，例如“允许 `git`，拒绝 `git push --force`，接入 `context7`”，要在每个 Agent 的配置文件里按各自的语法手工改写一遍，再分别维护。规则一多，各 Agent 之间就会慢慢漂移：某条拒绝规则只在一边生效，某个 MCP Server 只在一边接入，而且很难察觉。

一些高危规则（如允许 `sudo`、允许写入整个主目录）混在长长的允许列表里，也不容易被注意到。

## 解决方案

提供一个纯浏览器运行的网页工具，部署在 GitHub Pages 上。在工具里维护一份**中立规则集**：命令工具、MCP Server、各 Agent 的内置工具和权限规则。工具根据每个 Agent 定义，实时生成该 Agent 可以直接粘贴的权限配置和 MCP 配置。

- 首次打开时，用随站点发布的**预设**初始化**工作区**。预设包含常用命令工具、常用 MCP Server，以及 Claude Code、Antigravity、Codex CLI 的 Agent 定义。
- 输出页按 Agent 展示预览和复制按钮。用户可以整段复制以覆盖原有属性，也可以只复制某个决策数组的元素做增量合并。
- 遇到高危规则、冲突规则，或者某个 Agent 表达不了的规则时，只给出提示，不阻止生成。
- 工作区自动保存在浏览器本地，支持导入、导出 JSON 文件，也可以通过 GitHub Gist 在多台设备之间手动同步。
- 本站不收集任何数据：工作区只存在于浏览器本地和用户自己的 Gist 中。

## 实现决策

### 技术栈与部署

- 沿用 `hongzhao` 的技术栈和部署方式：Vite、React、Tailwind CSS v4、shadcn/ui（Base UI）、oxlint 和 oxfmt、Vitest，通过 GitHub Actions 部署到 GitHub Pages。
- **不沿用** `hongzhao` 的“不联网、不存储”约束。本站需要 localStorage 和 Gist 同步。
- 构建产物注入 CSP，`connect-src` 只放行 `'self'` 和 `https://api.github.com`。不引用 CDN，依赖全部随站点打包。
- PWA 由 `vite-plugin-pwa` 生成，只预缓存站点文件，不做运行时缓存，更新需要用户确认。
- 界面只提供简体中文，文案放在 locale 文件中，组件通过 i18n 读取。默认深色主题，viewport 不禁止缩放。
- 纯逻辑模块不包含界面文案：出错时返回原因码，由界面层翻译。

### 模块划分

- **工作区模型**：工作区的类型定义、校验与版本迁移。
- **工作区操作**：对工作区做所有修改的纯函数，包括增删改各类条目、修改标识、级联删除、合并预设、重置、导入。每个操作接收旧工作区，返回新工作区或原因码。
- **生成**：纯函数，输入工作区、Agent 的内部 ID 和本机设置，返回该 Agent 的完整输出结果。模板代入、占位符展开、去重、排序、跳过判定、JSON 转 TOML 都是它的内部实现，不单独暴露。
- **规则提示**：高危与冲突判定。规则列表也要直接显示这两种提示（故事 54），因此它作为纯函数与生成并列导出，由生成和规则列表共用，不属于生成的内部实现。
- **Gist 客户端**：封装 GitHub Gist API，`fetch` 由调用方注入。提供“推送（无 ID 时创建）”和“拉取”，返回结果或原因码。
- **持久化**：在 localStorage 中读写工作区、本机设置和 Gist 设置，三者分键存储。读写失败时返回原因码，不抛异常。
- **预设**：源码按实体拆分，每个 Agent 定义一个文件，命令工具、标签、MCP Server、共享权限规则各一个文件，在模块加载时合成一份默认工作区。
- **界面**：顶部导航包括权限规则、工具、MCP Server、标签、Agent、输出、同步（含导入、导出、Gist、合并预设、重置为预设、本机设置）。

### 工作区结构

工作区是单个 JSON 对象，所有属性名使用 snake_case。

- `schema_version`：整数，当前为 `1`。
- `updated_at`：最近一次修改的时间（ISO 8601），用于同步前的比较。
- `tags`：每项包含内部 ID、标识、名称。
- `command_tools`：每项包含内部 ID、标识（即命令本身，如 `git`、`./gradlew`）、可选描述、标签 ID 列表、高危标记。
- `mcp_servers`：每项包含内部 ID、标识（即输出中的 Server 名）、内容（JSON 对象）、可选描述、标签 ID 列表、高危标记。
- `agents`：每项包含：
  - 内部 ID、名称、可选描述；
  - `built_in_tools`：内部 ID、标识、可选描述、标签 ID 列表、高危标记、写入类标记、有模式模板、无模式模板；
  - 可选的 `permission_output`：属性路径（点分）、作用域列表（名称、路径、可选说明）、决策键名映射、命令工具的有模式与无模式模板、MCP 工具的有模式与无模式模板；
  - 可选的 `mcp_output`：风格（`json` 或 `toml`）、属性路径、作用域列表。
- `rules`：每项包含内部 ID、工具引用（工具类型加内部 ID）、模式（可为空）、决策（`allow`、`ask`、`deny`）、高危标记。指向内置工具的规则通过该内置工具隐含归属的 Agent。

约定：

- 条目之间一律用内部 ID 引用，因此修改标识不需要改动引用。内部 ID 不在界面上显示。
- 预设中的内部 ID 是固定值，“合并预设”按内部 ID 判断条目是否已存在。
- 标识在同一类条目内唯一。内置工具的标识在所属 Agent 内唯一。Agent 以名称作为标识，名称在全部 Agent 中唯一。
- 同一个 Agent 的决策键名不能重复（留空的除外），否则 JSON 中后一个决策会覆盖前一个。
- 标签被删除后，工具上残留的标签 ID 保留不动，由界面显示为带警告符号的“已删除的标签”；残留的 ID 同样不在界面上显示。
- 不存放 Gist Token、Gist ID 和本机设置。

### 模板与占位符

- 命令工具模板使用 `{command}` 和 `{pattern}`。例如 Claude Code 的无模式模板为 `Bash({command} *)`，有模式模板为 `Bash({command} {pattern} *)`；Antigravity 的两个模板分别为 `command({command})` 和 `command({command} {pattern})`。
- MCP 工具模板使用 `{server}` 和 `{pattern}`。例如 Claude Code 为 `mcp__{server}` 和 `mcp__{server}__{pattern}`；Antigravity 为 `mcp({server}/*)` 和 `mcp({server}/{pattern})`。
- 内置工具模板使用 `{pattern}`，例如 `Read` 与 `Read({pattern})`、`read_file(*)` 与 `read_file({pattern})`。
- 根据模式是否为空选择对应模板。所需模板为空时，该规则进入跳过的规则。
- 路径占位符 `{{home}}`、`{{user}}` 在输出时展开，作用于规则模式和 MCP Server 内容。`{{home}}` 按操作系统分别展开为 `/home/<用户名>`、`/Users/<用户名>`、`C:\Users\<用户名>`。本机设置不完整时保留原样，并产生提示。
- 环境变量占位符 `${VAR}` 不做任何处理，原样输出。

### 生成规则

- 每个 Agent 的权限输出包含全部共享规则，以及该 Agent 内置工具上的规则。MCP 输出包含全部 MCP Server，按 Server 的标识排序，与规则的排序方式一致。
- 输出顺序与规则列表的自动排序一致：先按工具类型（命令工具、MCP 工具、内置工具），再按工具标识，最后按模式。
- 同一决策内按最终字符串去重。
- 跳过的规则：决策键名为空，或所需模板为空。没有 `permission_output` 的 Agent 不产生跳过的规则，只给出“不输出权限”的说明。
- 冲突提示：同一工具、同一模式出现不同决策。
- 高危提示，只针对 `allow` 规则，满足任一条件即提示：
  - 所指工具被标记为高危；
  - 规则本身被标记为高危；
  - 所指内置工具被标记为写入类，且模式为空，或为 `/`、`~/`、`{{home}}/`。
- 权限预览按属性路径生成完整嵌套的 JSON。“复制”文本是属性路径最末一段的键值对，不带外层花括号。“复制内部”文本是该决策数组的元素，以逗号和换行分隔，不带方括号。
- JSON 风格的 MCP 输出：预览按属性路径完整嵌套。“复制”是最末一段键值对。“复制内部”是各 Server 的键值对，以逗号分隔。MCP Server 的描述不进入输出。
- TOML 风格的 MCP 输出：每个 Server 生成 `[<属性路径>.<标识>]` 表，嵌套对象（如 `env`）生成子表，数组和标量按 TOML 语法输出。无法表达的值（如 `null`）跳过该字段并产生提示。只提供“复制”。
- 输出不保证在目标 Agent 中一定有效。本工具只负责按 Agent 定义代入。

### 生成结果的形态

生成函数为每个 Agent 返回一个结构化结果，界面只负责展示：

- 权限节（可缺省）：预览文本、复制文本、按决策划分的复制内部文本、作用域列表；
- MCP 节（可缺省）：风格、预览文本、复制文本、复制内部文本（仅 JSON 风格）、作用域列表；
- 跳过的规则列表，每项带规则引用和原因码；
- 提示列表，每项带类型（高危、冲突、占位符未展开、TOML 字段跳过）、相关规则或 Server 的引用。

### 工作区操作

- 删除命令工具、MCP Server 或内置工具时，同时删除指向它的规则。界面在确认对话框中显示受影响的规则数量，数量由同一模块提供的查询函数计算。
- 删除 Agent 时，同时删除它的内置工具，以及指向这些内置工具的规则。
- 删除标签时，不修改引用它的工具。
- 合并预设：逐类添加预设中存在、工作区中不存在（按内部 ID 判断）的条目，不修改已有条目。若预设条目的标识与工作区已有条目冲突，跳过该条目并报告。
  - 跳过的预设标签由同标识的已有标签代替：新增的工具上引用该预设标签的地方改为引用已有标签，不产生悬空引用；报告中的跳过条目注明这一点。已有的工具保持不变。
- 重置为预设：用默认工作区整体替换。
- 导入：解析 JSON，校验结构；`schema_version` 较旧则迁移，较新或结构无效则返回原因码，原工作区不变。
- 每次修改都更新 `updated_at`。导入和 Gist 拉取例外：保留传入工作区自带的 `updated_at`，这样同步前比较双方的修改时间才有意义。

### 持久化

- 工作区在每次修改后写入 localStorage。读取时若数据缺失或无效，回退到预设并提示。
- 本机设置（操作系统、用户名）和 Gist 设置（Token、Gist ID）各用独立的键，只存在本机。
- 导出文件名包含日期，内容即工作区 JSON。

### Gist 同步

- 推送：没有 Gist ID 时，创建 Secret Gist，文件名为 `agent-weave.json`，描述说明来源，返回并保存新 ID；有 ID 时更新该文件。
- 拉取：读取该 Gist 中 `agent-weave.json` 的内容，再交给导入流程校验。文件缺失或内容被截断时返回原因码。
- 推送前和拉取前都先读取远端，界面并列展示远端与本地的 `updated_at`，由用户确认后再覆盖。
- 原因码至少区分：Token 无效或权限不足、Gist 不存在、文件缺失、网络失败、远端内容无效。另有 `rateLimited`，表示超出 GitHub API 的调用频率限制。
- Gist ID 一栏也接受 Gist 页面的网址，从中取出 ID。
- 拉取可以不填 Token：知道 ID 就能匿名读取 Secret Gist。推送仍需要 Token。
- 不做自动同步，也不做合并。

### 预设内容

- 共享规则取 Claude Code 与 Antigravity 两份实际配置的并集，并按正确性整理：
  - 去掉被更宽规则完全覆盖的冗余规则（如已有 `sudo` 拒绝时去掉 `sudo rm` 拒绝）；
  - 去掉不是真实命令名的条目（如 `ripgrep`、`tealdeer`）；
  - 保留整体允许 `docker` 加特定 `docker run --privileged` 拒绝这类组合，因为各家都是 deny 优先。
- 每个 MCP Server 都有一条共享的 `allow` 规则，即逐个 Server 允许，不设“全部 MCP”的概念。
- 脱敏：个人绝对路径改为 `{{home}}` 或 `~` 形式，`filesystem` MCP 的根目录参数改为 `{{home}}`。MCP 内容中自带的 `description` 字段挪到 MCP Server 的描述字段。
- 预设高危工具：`rm`、`sudo`、`dd`、`mkfs`、`chmod`、`chown`、`curl`、`wget`、`nc`、`socat`。
- 标签按社区通行的工具用途大致分配，一个命令可以有多个标签。
- Claude Code：
  - 权限属性路径为 `permissions`，作用域包括用户级 `~/.claude/settings.json`、项目级 `.claude/settings.json`、本地级 `.claude/settings.local.json`；
  - 内置工具包括 `Read`、`Edit`、`WebFetch`、`WebSearch` 等；
  - MCP 为 JSON 风格，属性路径为 `mcpServers`，作用域包括项目级 `.mcp.json` 和用户级 `~/.claude.json`。
- Antigravity：
  - 权限属性路径为 `userSettings.globalPermissionGrants`，主作用域为 `~/.gemini/config/config.json`（共享配置，IDE、App、CLI 共用）；
  - 第二个作用域是 `~/.gemini/antigravity-cli/settings.json`，说明中注明该文件的属性名为 `permissions`，粘贴后需要改键名；
  - 内置工具包括 `read_file`、`write_file`、`read_url`、`execute_url`，其中 `write_file` 标记为写入类；
  - MCP 为 JSON 风格，属性路径为 `mcpServers`，作用域包括 `~/.gemini/config/mcp_config.json` 和工作区级 `.agents/mcp_config.json`。
- Codex CLI：没有权限输出；MCP 为 TOML 风格，属性路径为 `mcp_servers`，作用域包括 `~/.codex/config.toml` 和项目级 `.codex/config.toml`。

## 测试决策

- 好的测试只验证外部行为：给定输入的工作区，断言生成结果或操作后的工作区，不断言内部函数的调用方式和中间结构。重构模板代入、排序等内部实现时，测试不需要改动。
- 测试接缝如下，不另设更细的接缝：
  - **生成接缝**（主接缝）：覆盖有模式与无模式模板的选择、占位符展开与未展开提示、去重、排序、各类跳过原因、高危的各个判定条件、冲突、权限预览的完整嵌套、复制文本与复制内部文本、JSON 风格与 TOML 风格的 MCP 输出（含嵌套表与 `null` 字段）、没有权限输出的 Agent。
  - **工作区操作接缝**：覆盖校验失败、旧版本迁移、新版本拒绝、合并预设（只新增、标识冲突时跳过）、重置、修改标识后输出随之变化、各类级联删除与受影响规则数量、删除标签后的悬空引用。
  - **Gist 接缝**：注入假的 `fetch`，覆盖首次推送自动创建、带 ID 推送更新、拉取、Token 无效、Gist 不存在、文件缺失、网络失败。
  - **预设**：复用以上接缝。预设工作区必须通过校验；对每个预设 Agent 运行生成接缝，做快照测试。
- 已有做法参考 `hongzhao`：纯函数放在不依赖 React 和 DOM 的模块中，测试放在 `test/` 下，以 `*.test.ts` 命名，由 Vitest 运行。
- 界面不写组件测试，在浏览器中实际验证。重点检查复制按钮、确认对话框、Gist 流程，并确认运行时只向 `api.github.com` 发出请求。
- 提交前运行与 `hongzhao` 相同的校验命令：格式检查、lint、类型检查、测试、构建。

## 不在范围内

- Codex CLI 的权限输出：它的命令规则是 Starlark `prefix_rule`，路径与网址规则在另一套 beta 配置中，官方标注为实验性功能。
- 除 Gist 以外的同步方式：Dropbox、Google Drive、OneDrive、WebDAV 等。
- 从现有 Agent 配置文件反向导入规则。
- 多套规则集，以及按 Agent 勾选共享规则或 MCP Server。
- 自动同步、冲突合并。
- 密钥管理：本工具不存储、不检测、不加密任何密钥。
- 校验输出在目标 Agent 中是否有效。
- 在作用域之间切换输出内容。作用域只作提示。
- 直接写入本地配置文件。
- 简体中文以外的界面语言。
- 规则的手动拖拽排序。

## 补充说明

- 术语见 `GLOSSARY.md`，Agent 定义采用数据加模板的方式，见 `docs/adr/0001-agent-definition-as-data.md`。
- 各 Agent 格式的调研截至 2026-10-23，要点如下：
  - Claude Code 的 Bash 规则以 `Bash(git push *)` 为推荐写法，旧的 `:*` 写法仍然兼容。`mcp__*` 不能用于 `allow`。
  - Antigravity 官方文档只公开了 CLI 的 `~/.gemini/antigravity-cli/settings.json`（`permissions`）。`~/.gemini/config/config.json` 中的 `userSettings.globalPermissionGrants` 来自用户本机的实际配置，是 IDE、App、CLI 共用的共享配置。Antigravity 的远程 MCP 使用 `serverUrl` 而非 `url`；本工具不转换这个差异。
  - Codex CLI 的 MCP 配置是唯一的 TOML 风格，即 `[mcp_servers.<name>]`。
  - 主流 Agent 大多采用 Claude 风格的 `mcpServers` JSON。VS Code（`servers`）、Zed（`context_servers`）、OpenCode（`mcp`）的根键不同，可以通过 Agent 定义的属性路径适配。
- 用户提供的原始配置副本位于 `docs.local/`（不纳入版本控制），只用于整理预设，不直接打包。
