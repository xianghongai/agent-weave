# 预设按界面语言合成，工作区中的文字不随语言改变

界面增加英文后，预设中给人看的文字（标签名、描述、高危说明、作用域的名称和说明）也需要英文。但这些文字在初始化、合并预设、重置为预设时会复制进工作区，之后就是用户数据，会随导出文件和 Gist 流转。我们为每种界面语言各合成一份预设工作区，两份的条目结构和 ID 完全相同，只有文字不同，并且都打包进站点。初始化、合并、重置时取当前界面语言的那一份。切换界面语言只改变界面文字，不改动工作区。

## Decision

- `presets/locales/` 下每种语言一个语言文件，构建时按语言分别合成；单元测试要求各语言合成出的工作区去掉文字字段后完全相同。
- `src/lib/` 不读取界面语言，由界面层把当前语言作为参数传入。
- 合并预设仍然按 ID 跳过已有条目，所以切换语言后再合并，工作区可能中英混杂；想要整套另一种语言的预设，就重置为预设。
- 界面语言和主题一样只保存在当前设备的应用 store 中，不进入工作区、导出文件和 Gist；没有选择过时跟随浏览器语言。

## Considered Options

- **预设只有中文**：实现最简单，但英文用户拿到的描述全是中文。
- **每种语言各合成一份并打包（采用）**：合并、重置逻辑不变，`createPresetWorkspace()` 保持同步；代价是预设随语言数量成倍增加。
- **按语言动态加载预设**：只加载当前语言的预设，但 `createPresetWorkspace()` 和依赖它的操作都要变成异步，影响面大。
- **切换语言时重新翻译工作区中的预设文字**：要区分哪些文字被用户改过，会改写用户数据，并且触发同步。
- **把手动选择的语言放进网址参数**：适合不使用本地存储的站点；本站本来就有持久化的应用 store，语言放进去和主题保持一致。

## Consequences

- 预设文字新增或修改时，要同时补齐每种语言的语言文件，缺失的键由单元测试拦截。
- 工作区中的文字一旦写入就不再跟随界面语言，用户看到的描述语言可能和界面语言不同。
